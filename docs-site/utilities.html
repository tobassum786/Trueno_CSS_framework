Utilities

Utilities are single-purpose, composable helpers for spacing, alignment, display, and visibility. They carry !important so they win against component styles, and they are prefixed with u- (spacing is the exception) so they are easy to spot in markup. Source: src/utilities/

tree
utilities/
├── _spacing.scss   → m-* / p-* spacing scale
├── _helpers.scss   → u-* alignment, display, visibility, float
├── _motion.scss    → u-anim-* / u-transition-* motion utilities
└── _gradients.scss → u-bg-* / u-text-* / u-border-* gradient utilities

How utilities work

A utility is a micro-class that does one thing. Stack them on an element to compose layout, and know two rules keep them reliable:

  • They are !important. A utility always beats component styles, so it is impossible for your base CSS to cancel it by accident.
  • They are composable. class="mt-lg u-text-center u-d-flex" is a perfectly valid util-only class list.
⚠️

Because utilities use !important, overriding one requires a more specific selector. If you repeat the same utility three times, promote it to a component class instead.

💡

mx-auto is the idiomatic centerer, but it only centers an element that has a constrained width — pair it with a grid column such as col-6 or an inline width.

Example markup

HTML
<!-- Spacing all sides -->
<div class="m-md">…</div>

<!-- Vertical rhythm: top margin + left/right padding -->
<div class="mt-lg px-xl">…</div>

<!-- Reset padding on a component -->
<div class="card p-0">…</div>

<!-- Center a constrained block -- the col gives it width -->
<div class="col-6 mx-auto">…</div>

Code reference — how it's generated

scss
@each $prop, $abbr in (margin, m), (padding, p) {
  @each $dir, $abbr-dir in (top, t), (bottom, b), (left, l), (right, r),
                          (top-bottom, y), (left-right, x), (all, '') {
    @each $size-name, $size-value in (0, 0), (xxs, $spacing-xxs), (xs, $spacing-xs),
                                     (sm, $spacing-sm), (md, $spacing-md), (lg, $spacing-lg),
                                     (xl, $spacing-xl), (xxl, $spacing-xxl), (auto, auto) {
      // emits .#{$abbr}#{$abbr-dir}-#{$size-name} with !important
    }
  }
}

Visibility & accessibility

.u-sr-only attaches a label that screen readers announce but users never see

The trash icon is decorative (aria-hidden); the label is .u-sr-only.
ClassEffect
.u-hiddenvisibility: hidden !important — invisible but still reserves space
.u-invisibleExtends %visually-hidden — removed visually, kept for screen readers
.u-sr-onlyAlias of .u-invisible — the accessibility standard for "screen reader only"

</button>

3. Gradients — u-bg-gradient-*

A complete gradient utility layer built on the same color plates that drive every other component. Background, text, and border gradients are all first-class citizens, and every gradient exposes its stops as CSS custom properties so you can tune it at runtime without writing a new class. Source: src/utilities/_gradients.scss.

Runtime-tuning variables

Custom propertyDefaultPurpose
--tr-grad-angle135degGradient direction. Overridden by .u-gradient-to-* modifiers.
--tr-grad-stop-1Plate step (see hue table)First color stop.
--tr-grad-stop-2Plate step (see hue table)Second color stop.
--tr-grad-stop-3(unset)Third color stop, used by -3 variants. Falls back to a 2-stop gradient when omitted.
--tr-surfacevar(--tr-white)Inner color used by .u-border-gradient* to mask the gradient inside the border. Override in a dark theme.
💡

Because every variable is read with var(..., fallback), you can override any stop on a single element with an inline style — the rest of the class's defaults are preserved.

HTML
<div class="u-bg-gradient-primary"
     style="--tr-grad-stop-1: var(--tr-blue-200); --tr-grad-stop-2: var(--tr-blue-900);">
  …
</div>

Direction modifiers set --tr-grad-angle and compose with any gradient utility: <div class="u-bg-gradient-primary u-gradient-to-r">…</div>.

Text gradients render with color: transparent. They are presentational — the underlying HTML text is still copied, indexed, and read aloud — but always provide a color fallback on a parent or an aria-label if the text is critical for assistive tech.

Border gradients

.u-border-gradient and .u-border-gradient-{hue} render a gradient stroke around an element. The inner color is controlled by --tr-surface — set it once on .theme--dark and every border gradient adapts.

Gradient best practices

  1. Pick a direction modifier, not a custom angle. .u-gradient-to-tr is more discoverable than a hand-rolled --tr-grad-angle: 45deg inline style — and it composes cleanly with any other utility.
  2. Use -3 variants for hero sections. The 3-stop gradients have more visual depth; reserve 2-stop gradients for inline elements (badges, buttons, list accents).
  3. Use .u-text-gradient-trueno for brand headlines. It's the framework's signature and reads well at large sizes.
  4. Set --tr-surface in dark themes. Border gradients otherwise show a white inner mask. Set it once on .theme--dark and every border gradient on the page adapts.
  5. Don't animate gradient stops directly. For motion, pair the gradient with the existing .u-anim-gradient-shift utility from the motion layer — it already respects prefers-reduced-motion.

Utility best practices

  1. Use utilities for one-off adjustments. Repeating mb-md three times? Promote it to a component class.
  2. Compose freely. <div class="m-md p-md u-text-center u-d-flex"> is valid, readable, and the point of the system.
  3. Never strip !important. Override with a more specific selector or a component, never by editing the utility.
  4. Prefer .u-sr-only over hiding tricks. It conveys content to assistive tech without affecting the visual design.
  5. Reach for the grid first. For multi-element layouts, use .row/.col or .grid before compositing floats and margins by hand.
